# playgrounds/ — 手工验证场景

存放需要人工观察的验证场景。这些场景**不是游戏内容**，只用于确认某段逻辑在真实运行时表现正常。

## 收录范围

- 需要肉眼观察表现（布局、日志、时序）的场景；
- 不适合写进 `tests/` 的交互式验证；
- 临时排查用的场景（确认后应删除，不要长期堆积）。

自动化测试放 `tests/`，走 `--script` 无头运行；本目录的场景走编辑器或命令行直接运行。

## 场景清单

| 场景 | 用途 | 驱动脚本 |
| --- | --- | --- |
| `battle_sandbox.tscn` | 逻辑流水沙盒：展示行动队列与指针位置，逐次行动/逐轮/整场推进，实时打印阶段流水、弹刀结果与资源点变动 | `battle_sandbox.gd` |
| `battle_screen.tscn` | 可操作战斗场景：玩家真的选进攻/防御/目标/模组，被进攻时开启限时反应窗口，是本阶段的可玩入口 | `battle_screen.gd` |

## 运行方式

```bash
godot --path . res://playgrounds/battle_screen.tscn
godot --path . res://playgrounds/battle_sandbox.tscn
```

或在编辑器中打开场景后按 F6 运行。

## 主场景例外

本目录的场景默认**不设为主场景**。当前唯一例外是 `battle_screen.tscn`——它是原型期唯一能"真的玩一下"的入口，
已设为 `run/main_scene`，按 F5 直接进入。正式 UI 落地后应迁出本目录。

## 界面说明（battle_screen）

**等距战场**：斜 45° 菱形网格，上敌方、下我方，每方三人。单位站在格点上，按屏幕 y 排序遮挡（远的先画），
脚下有椭圆影子；头顶显示名字与 HP，血条随剩余血量变红。

**提示色**（脚下菱形与轮廓描边**同色**，取色集中在 `BattleScreen._marker_color_for`）：

| 颜色 | 含义 |
| --- | --- |
| 青色 | 当前行动人 |
| 青色 + 描边 | **这个敌人现在可以点**（鼠标悬停会转成下面那个黄） |
| 黄色 | 鼠标正停在这个敌人身上 |
| 红色 | 正在被进攻（弹刀窗口中的防守方） |

- **点选目标**：**二选一阶段就能直接点敌人**（点敌人 = 进攻它），不必先按「进攻」；`进攻` 之后同样可以直接点，
  也可以用侧栏按钮。可点的敌人会亮起青色描边——只画脚下那一小块菱形，玩家根本看不出能点。
- **队列面板**：每个单位一行，`▶` 标出当前操作人，行内显示阵营、本轮点数、HP 与资源点圆点。
- **操作区**：按流程切换——`进攻/防御` → `选目标` → `选模组`；敌方打到我方时切换为**反应窗口**。
- **反应窗口**：**不显示倒计时**，窗口长度就是"敌人攻击过来"的演出时长——进攻方精灵泛白放大起手，
  然后一块方块**沿等距方向**飞向防守方、防守方精灵越来越红，**方块抵达＝窗口结束**，没按出来就是不对抗。
  侧栏滑条可实时调窗口时长（0.8~6.0 秒）。
- **键盘**：**进攻 `Q`/`W`/`E`，弹刀 `A`/`S`/`D`**（都按"石头剪刀布"同序）。两套键位分开是为了让手在反应时
  不用切语义——进攻在键盘左上排、弹刀在中排，物理位置分得开。**不设不对抗键**——没按出来本身就是不对抗。
- **鼠标**：所有选择都能点——行动二选一、选目标、选模组都有按钮；**敌人可以直接点**（含二选一阶段）。
- **弹刀规则提示**：常驻在**底部横条**（模组正式名待定，界面先用机制名）。
- **战斗日志**：按发生顺序打印管线阶段、任意时刻窗口、弹刀结算与资源点变动。

### 尺寸与缩放

战场按 **640×360** 绘制（见 `docs/design/art_requirements.md` 第一节），再整数倍 **2×** 放大到窗口 **1280×720**。
HUD 位于窗口坐标、不随战场缩放，所以文字是原生分辨率、清晰可读。

美术资源缺失时会自动退化为同尺寸色块并在控制台告警，**没有美术也能跑通完整流程**。

## 界面说明（battle_sandbox）

- **状态栏**：当前轮次与战斗状态。
- **队列面板**：每个单位一行，`▶` 标出当前操作人，行内显示阵营、生命值与资源点。
- **日志面板**：按发生顺序打印管线阶段、任意时刻窗口、弹刀结算与资源点变动。
- **按钮**：`执行一次行动` 逐次推进（队列走完后再按会自动开新一轮）、`跑完一轮`、`跑完整场`、`重置`。

## 边界

- 两个场景的界面全部由脚本在 `_ready()` 中构建，场景文件只保留根节点与脚本挂载，避免手改节点树。
- 表现层一律不碰战斗规则，规则只在 `features/battle/` 里，保证 `tests/` 与界面跑的是同一套逻辑。
- 等距坐标换算在 `core/iso_grid.gd`（纯数学、不碰场景树），**箱庭探索复用同一套**，不要另写一份。
- 战场点击拾取走 `_to_field(event.position)`（`event.position` + `get_global_transform_with_canvas()`），
  **不要用 `Node2D.get_local_mouse_position()`**——它读全局鼠标状态，注入事件时对不上，会让"点敌人"在测试里永远测不出来。
- 输入链路的自动化测试在 `tests/test_battle_input.gd`。鼠标用例**必须在真实窗口下跑**（`--headless` 收不到鼠标事件），
  且分辨率**故意取非 1280×720**，否则坐标换算的 bug 会被单位矩阵掩盖。
- 数值（伤害、疗愈、反应窗口时限）在原型阶段为占位值，见 `features/battle/battle_controller.gd` 与 `battle_screen.gd` 顶部常量说明。
